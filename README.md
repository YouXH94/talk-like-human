# talk like human

[English](README.en.md) · 简体中文

一个面向 **中文报告、进度汇报和技术解释** 的 Codex 写作技能。它把生硬、过度压缩的表述写成自然、连贯、容易理解的中文，同时保留事实、数字、条件和不确定性。

例如，把“并发场景未覆盖”说清楚为“目前还没测过多人同时操作时会怎样”。只有原文支持这些具体含义时，才这样展开。

## 它解决什么问题

有些文字术语很齐全，读者却难以看出发生了什么、做过什么检查、结果意味着什么。这个技能会根据材料，把关键对象、动作和信息之间的关系讲完整。

- **把抽象标签说具体。** 说明谁做了什么、哪里出现了问题，避免只留下“状态失步”“存在风险”等标签。
- **保留事实和确定程度。** “没测试”仍然是没测试，“可能有关”不会被写成“已经确定原因”。数字、单位、测试条件、例外和来源也要保留。
- **让结构符合内容。** 解释通常写成连贯段落；步骤、并列事项和比较可以使用列表，不强制套固定模板。
- **保持应有的专业程度。** 正式报告保持正式，技术说明保留准确术语，不靠玩笑、情绪或虚构经历制造“人味”。

它适合润色已有文字，也适合根据已提供的材料撰写中文说明。它不会替你查证原材料，也不会把缺失信息补成事实；实际效果取决于输入和使用的模型。

## 改写前后对比

以下均为**虚构案例和示范改写**，用于说明表达方式，不是实际项目记录或模型效果评测。案例一、二设定为检查人员本人写报告，因此允许使用第一人称；真实使用时，输入没有提供相应经历，就不能写“我检查了”。

### 1. 把已查清的问题讲具体

**改写前**

> 预约取消后，页面未恢复可预约状态。经排查，可用时段查询未过滤已取消记录，相关时段仍被判定为占用。建议完善查询条件，并补充取消后重新预约的验证。

**改写后**

> 预约已经取消了，但页面仍显示这个时段不能预订。我检查了查询逻辑，发现系统计算空闲时间时，仍把已经取消的预约算了进去。
>
> 建议查询时排除这些已取消的记录。修改后，再取消一条预约，试一下能不能重新预订原来的时段，确认这个问题已经解决。

**变化：** 把查询条件的问题展开为具体行为，并让修改建议和验证方法更容易跟上。

### 2. 说清楚已经检查和还没检查的部分

**改写前**

> 有用户反馈，文档权限移除后，已打开的页面仍可查看。目前仅核对了前端权限配置，尚未检查缓存和服务端权限判断，因此原因尚不明确。建议补查相关处理，并验证刷新页面、重新登录后的访问结果。

**改写后**

> 有用户说，自己的文档访问权限被移除后，原来打开的页面还能继续查看。
>
> 我目前只检查了前端的权限配置，还没查缓存和服务器是怎样处理这次权限变更的。建议继续检查这两部分，并分别试一下刷新页面、重新登录后还能不能打开文档，看看问题具体出在哪一步。

**变化：** 保留原因尚未确定的状态，把后续建议写具体，没有把建议写成已经执行的检查。

### 3. 让优化结果和测试条件一起被看见

**改写前**

> 在同一台服务器、5 万条商品数据、缓存已预热的条件下，优化前后各执行 20 次查询，平均搜索耗时由 2.4 秒降至 0.9 秒。当前结论仅适用于上述测试条件，冷缓存及多人并发场景尚未覆盖。建议补充相关测试后再评估上线。

**改写后**

> 这次测试中，商品搜索的平均耗时从 2.4 秒降到了 0.9 秒。测试用的是同一台服务器和同样的 5 万条商品数据，优化前后各测了 20 次，测试时缓存已经提前加载好了。
>
> 不过，缓存还没加载时搜索会有多快、多人同时搜索时会不会变慢，目前还没有测过。建议把这两种情况补测一下，再判断是否适合上线。

**变化：** 保留全部数字和测试条件，没有把一次有限测试扩大成“已经可以上线”。

## 安装到 Codex

这是一个独立的、仅包含指令与示例的技能，不需要额外 API Key、MCP 服务或运行脚本。使用它仍需你现有的 Codex 环境和模型访问权限。

### 方法一：让 Codex 安装

在 Codex 中输入：

```text
使用 $skill-installer，从 https://github.com/YouXH94/talk-like-human 安装 talk-like-human 技能。
```

### 方法二：手动安装固定版本

以下命令适用于 macOS / Linux 的终端，将 `v1.0.0` 安装到用户技能目录：

```bash
mkdir -p "$HOME/.agents/skills"
git clone --depth 1 --branch v1.0.0 https://github.com/YouXH94/talk-like-human.git "$HOME/.agents/skills/talk-like-human"
```

也可以从 [Releases](https://github.com/YouXH94/talk-like-human/releases) 下载 `talk-like-human-v1.0.0.zip`，解压后把 `talk-like-human` 文件夹放进 `~/.agents/skills/`。只供某个项目使用时，放进该项目的 `.agents/skills/`。

如果已经安装过同名技能，先确认现有内容和位置，避免多份同名技能并存。安装后可直接尝试调用；如果没有出现在技能列表中，重启 Codex 后再试。

目录位置与发现机制见 [OpenAI 官方技能文档](https://learn.chatgpt.com/docs/build-skills)。其他支持 `SKILL.md` 的工具可能也能使用这些指令，但本仓库没有验证其安装方式或兼容性。

## 怎么使用

**润色已有报告**

```text
使用 $talk-like-human 改写下面的中文报告。
面向熟悉业务的同事，保留事实、数字、来源、测试条件和不确定性。
只输出改写后的正文。

【粘贴原文】
```

**根据材料写进度说明**

```text
使用 $talk-like-human，根据以下记录写一段正式的进度说明。
区分已完成、未完成和建议事项，不补造检查、原因或结论。

【粘贴记录】
```

**查看改写差异**

```text
使用 $talk-like-human 润色以下文字，给出改写前后对比，并解释关键修改。
保留原文的正式程度，不改动引用、命令和代码。

【粘贴原文】
```

技能默认允许 Codex 根据任务自动选用，也可以通过 `$talk-like-human` 明确调用。默认只交付成稿；需要对比、解释或指定格式时，直接在请求中说明。用户明确指定的文体、术语、语气和长度优先。

## 使用边界与隐私

它主要服务于中文解释性写作；英文 README 是使用说明，不表示技能已经针对英文写作进行优化。它不是事实核查工具，也不承诺通过任何 AI 文本检测。代码、原样引用和机器可读内容应按任务要求保留。

技能包没有遥测、联网代码或外部服务依赖。你粘贴的文字仍由所使用的 AI 产品处理；本技能不会改变该产品的数据处理规则，也不会自动匿名化输入。涉及敏感信息时，应先自行脱敏。
